# viz — visual model of credence's math

Static plots that show how each piece of the credibility + ranking math
behaves. Useful for building intuition before tweaking constants and for
spotting when a change had unintended shape.

Plots are generated by running pure-numpy reproductions of the formulas — no
database, no SQLAlchemy. If a plot disagrees with the production code, the
plot is wrong; fix it.

## what's here

| script | what it shows | mirrors |
|---|---|---|
| `components.py` | expertise log curve, proximity distance decay, full `α·a + β·e + γ·p` surface, alignment redistribution fallback | `modules/credibility/{expertise,proximity,alignment,score}.py` |
| `dynamic.py` | Glicko-inspired credibility trajectories: agreement vs. divergence, effect of `DAMPEN`, `LEARNING_RATE`, community weight | `modules/credibility/dynamic.py` |
| `ranking.py` | weighted average vs. simple average, Bayesian prior shrinkage (phase 2) | `modules/ranking/ranking.py` + SPEC §phase 2 |

Generated PNGs land in `viz/output/`. They are committed so the plots are
reviewable in PR diffs without running anything.

## regenerate

```
pip install -r requirements.txt   # adds matplotlib
python -m viz.generate            # writes PNGs into viz/output/
```

Run from the `credence/` directory.

## MAINTENANCE — read before merging math or infra changes

**Any PR that changes the math or adds new infra must update viz/.** This is
how we keep the visual model honest.

Triggers — if your change touches any of these, you must update viz/:

- a constant in `modules/credibility/` (α, β, γ, MAX_N, THRESHOLD, LEARNING_RATE, DAMPEN, RD_FLOOR, …)
- the shape of any formula (expertise, proximity, alignment, dynamic update, ranking)
- a new credibility component (e.g. PageRank-style propagation in phase 4)
- a new infra stage that affects the data flow shown in plots (e.g. async
  workers, Kafka stream, FAISS neighborhoods) — add a dataflow diagram even
  if the math is unchanged
- a new phase from SPEC.md is implemented

What "update viz/" means concretely:

1. Mirror the new constant or formula in the relevant script. The scripts
   import nothing from `modules/` — they re-implement the math in numpy. Keep
   them in sync by hand.
2. Re-run `python -m viz.generate` and commit the regenerated PNGs.
3. If a new mathematical concept appeared (not just a constant tweak), add
   a new plot function and list it in the table above.
4. If a phase transition is implemented, add a section here describing what
   changed and what the new plots illustrate.

If you're skipping a viz update because the change is "trivial," write one
sentence in the PR description explaining why none of the existing plots
moved. That forces the check.
